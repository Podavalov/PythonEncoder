PythonEncoder

PythonEncoder — инструмент для защиты Python-скриптов с помощью шифрования, привязки к конкретной машине и ограничения срока действия. Исходный код упаковывается в зашифрованный исполняемый скрипт, который расшифровывается и выполняется только при соблюдении заданных условий (ключ, машина, время).
Возможности

    Шифрование исходного кода (XOR с производным ключом) – без ключа прочитать или запустить файл невозможно.

    Привязка к машине – можно ограничить запуск только на одной конкретной системе (или разрешить везде).

    Срок действия – задаётся количество дней, после которых скрипт перестаёт работать.

    Пакетная обработка – шифрует все .py файлы в директории, сохраняя структуру, с возможностью исключать определённые файлы/папки.

    Интерактивный режим – для тех, кто не хочет разбираться в параметрах командной строки.

Требования

    Python 3.6 или выше.

    Только стандартная библиотека (никаких дополнительных пакетов не требуется).

Установка

Просто скачайте три файла:

    encoder.py – основной движок защиты.

    fileCollector.py – сбор файлов и настройка исключений.

    main.py – интерфейс для пакетной обработки.

Поместите их в одну папку или в любое место на вашем компьютере. Для запуска используйте команды Python:

```bash
python encoder.py [команда] [аргументы]
python main.py [аргументы]
```
    Если Python у вас установлен как python3, замените python на python3.

Использование
1. Показать код текущей машины

Для привязки к конкретной машине нужно узнать её идентификатор:

```bash
python encoder.py machine
```
Вывод — 16-символьный код, который можно использовать в параметре --machine.
2. Защита одного файла

С помощью encoder.py protect можно зашифровать отдельный .py файл.
```bash
python encoder.py protect исходный.py -o защищённый.py --key МойКлюч --machine auto --expire-days 30
```
**Основные параметры:**

| Параметр | Описание |
| --- | --- |
| input | – исходный файл (обязательный). |
|-o, --output | выходной файл (если не указан, перезаписывает исходный). |
| --key | ключ шифрования (если не указать, будет сгенерирован случайный и вшит в файл). |
| --machine | привязка: any (везде), auto (к текущей машине) или конкретный 16-символьный код. |
| --no-machine | то же, что --machine any. |
| --expire-days | срок действия в днях (0 или без указания – бессрочно). |

После выполнения получится защищённый файл, который можно запускать как обычный Python-скрипт:
```bash
python защищённый.py
```
При запуске он проверит ключ, привязку и срок действия. В случае ошибки выведет соответствующее сообщение.
3. Запуск защищённого файла

Если вы не хотите запускать файл напрямую, можно использовать команду run:
```bash
python encoder.py run защищённый.py
```
Это эквивалентно python защищённый.py.
4. Пакетная защита (main.py)

main.py предназначен для шифрования всех .py файлов в заданной директории (рекурсивно). Результат помещается в новую папку с суффиксом _encrypted (или с номером, если такая уже существует). Оригинал остаётся нетронутым.
Быстрый старт (автоматическая генерация ключа, без привязки, бессрочно)
```bash
python main.py /путь/к/проекту --quick
```
С указанием параметров
```bash
python main.py /путь/к/проекту --key МойКлюч --machine auto --expire-days 90 --exclude tests/ --exclude setup.py
```
Интерактивный режим

Если добавить --interactive, программа задаст вопросы:
```bash
python main.py --interactive
```
Вы сможете выбрать:

    Быстрый старт (автоматически).

    Ручную настройку всех параметров.

    Продвинутый режим с дополнительными проверками.

Параметры main.py

| Параметр | Описание |
| --- | --- |
| directory | путь к директории (если не указан, будет запрошен интерактивно). |
| --key | общий ключ для всех файлов (если не указан, генерируется случайный). |
| --machine | привязка: any, auto или код. |
| --no-machine | отключает привязку (то же, что --machine any). |
| --expire-days | срок действия в днях. |
| --exclude | добавить файл или шаблон для исключения (можно указать несколько раз). |
| --show-excluded | показать список стандартных исключений и выйти. |
| --interactive | включить интерактивный режим (даже если указаны другие параметры, они могут быть переопределены). |
| --quick | быстрый режим (случайный ключ, без привязки, бессрочно). |

Исключения (какие файлы не шифруются)

По умолчанию из обработки исключаются многие служебные файлы, например:

    setup.py, settings.py, __init__.py

    тестовые файлы (*_test.py, test_*.py)

    файлы миграций (*/migrations/*.py)

    файлы конфигурации (local_settings.py, dev_settings.py и т.д.)

    файлы, содержащие _encrypted в имени

    другие файлы, перечисленные в EXCLUDED_PATTERNS внутри fileCollector.py.

Вы можете добавить свои исключения:

    в командной строке: 
 ```bash
    --exclude my_script.py --exclude docs/*.py
```
    в интерактивном режиме (продвинутая настройка).

Исключения применяются до создания копии директории, поэтому зашифрованные файлы не попадут в выходную папку.
Как это работает (кратко)
 ```
    Исходный код читается как строка.

    Из ключа и магической константы (MAGIC = b"PythonEncoder|v1|") вычисляется производный ключ с помощью SHA-256.

    Метаданные (срок действия и код машины) шифруются XOR с этим ключом и сохраняются в base64.

    Исходный код шифруется XOR и тоже сохраняется в base64.

    Всё упаковывается в шаблон-загрузчик, который при запуске:

        расшифровывает метаданные;

        проверяет машину и срок;

        расшифровывает код;

        выполняет его в специальном пространстве имён (с подменой глобальных переменных, чтобы импорты и обращения к __file__ работали корректно).

```
    Сохраните ключ! Если вы использовали сгенерированный ключ, его необходимо сохранить, иначе расшифровать файлы будет невозможно. В пакетном режиме ключ выводится в конце.

    Не изменяйте защищённые файлы. Любое изменение сломает структуру (метаданные или код) – файл перестанет работать.

    Привязка к машине использует идентификаторы, которые могут измениться (например, смена сетевой карты, переустановка ОС). В таких случаях запуск станет невозможным.

    Срок действия проверяется по системному времени. Изменение времени назад может обойти ограничение (но для большинства сценариев это не критично).


Примеры
Зашифровать один файл с автоматической генерацией ключа и привязкой к текущей машине
```bash
python encoder.py protect my_script.py --machine auto --expire-days 30
```
Зашифровать весь проект, исключая папку tests
```bash
python main.py ./my_project --exclude tests/ --expire-days 90
```
Интерактивная пакетная защита
```bash
python main.py --interactive
```
Следуйте подсказкам.
Показать код машины
```bash
python encoder.py machine
```
